We are pleased to announce that Opal 6.0 is now available. Opal is OBiBa’s core data management application for biobanks.

This is a major release, with the following key changes:

  • New configuration database: Opal's own configuration (projects, permissions, users, registered databases...) is no longer stored in OrientDB but in an embedded H2 database, or optionally in PostgreSQL. The migration runs by itself at the first start of the new version and reports what it migrated in the startup log.
  • Project-internal database: a project can now be created with its own storage database, managed by Opal and deleted with the project. Users allowed to create projects no longer depend on a system administrator to provision storage.
  • DataSHIELD usage quotas: R execution time and session time can be limited per user, group or system-wide, over a rolling window. Users can see their consumption on their profile page, and administrators on the DataSHIELD administration page.
  • OpenTelemetry export: logs, DataSHIELD traces (one trace per session, with its R operations) and DataSHIELD metrics can be sent to an OpenTelemetry collector. Nothing is exported unless it is explicitly configured.
  • Storage safeguards: Opal watches the free disk space of the volumes it writes to, refuses large writes before the disk is full, and periodically forces the open H2 databases to disk.
  • Security improvements: "Import from Opal" now verifies the certificate and host name of the remote server, file access control is enforced on every read path, DataSHIELD symbol writes go through the restricted parser, and disabling another user's two-factor authentication requires a permission.

The Opal documentation has been updated accordingly. In particular, the Docker installation section was rewritten: the Opal image no longer needs a database server to run, and the documented setups range from a standalone Opal with a DataSHIELD ready R server to complete stacks with data databases.

For Kubernetes deployments, the Opal Helm chart has been updated accordingly (version 2.0.0). Please follow the Helm chart upgrade instructions when moving an existing release to this version.

The Opal client libraries have also been updated to support these new features: opalr (R, version 3.7.0) and obiba-opal (Python, version 6.2.0).

Upgrading from Opal 5.x requires some attention from the system administrator: back up your data before starting, decide where the configuration database will live, and review the trusted certificates of remote Opal servers. Please read the Opal upgrade notes before upgrading.
