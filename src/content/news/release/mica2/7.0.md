title: Mica 7.0 Released
date: 2026-09-19T12:00:00Z # after Agate 5.0, same day
product: mica
summary: 2FA sign-in feedback, open redirect closed, XSS hardening, credentials kept out of logs
---

We are pleased to announce that Mica 7.0 is now available. [Mica](/products/mica/) is OBiBa's data web portal for epidemiological studies and harmonization initiatives.

This is a security-focused major release, with the following key changes:

- **Two-factor authentication feedback**: a wrong 2FA code now keeps the 2FA step open and shows a dedicated "Invalid or expired code" message, instead of sending the user back to the credentials form with a generic authentication failure.
- **Open redirect closed**: the `redirect` parameter of the sign-in, sign-up and `/check` pages only accepts a path on the Mica server or a URL on the Agate server.
- **Credentials kept out of logs**: the remote credentials used when importing studies from another Mica are sent in request headers instead of query parameters, and session IDs no longer appear in logs.
- **XSS hardening**: Mica now sends the `X-Content-Type-Options`, `Referrer-Policy` and (over TLS) `Strict-Transport-Security` response headers; Markdown descriptions are sanitized with DOMPurify; custom page names are restricted to a safe character set; and uploaded files are only displayed inline for PDF, raster images, plain text, CSV and TSV, any other type (SVG, HTML, XML...) being downloaded as an attachment.
- **Authorization on administration endpoints**: changing the log levels and managing custom translations now require the `mica-administrator` role.
- **Roles mapping applied everywhere**: when Agate groups are mapped to Mica roles through the `roles.<role>` settings, the mapped groups are now used when notifying data access officers, reviewers and editors, when listing users, when signing up users and when contacting the site, instead of the Mica role names. Only roles mapped to a single group are expanded, so that a role granted to the intersection of several groups does not leak notifications to every member of each group.

**Breaking change:** if you have overridden Mica's templates (`signin.ftl`, `libs/signin-scripts.ftl`, `libs/scripts.ftl`, `compare.ftl`, `dataset.ftl`, `variable.ftl`), they must be revised from the 7.0 versions; in particular `libs/scripts.ftl` must load DOMPurify, otherwise Markdown descriptions are displayed as escaped text. Custom page names, links redirecting to an absolute URL after sign-in, and scripts calling the study import or the administration endpoints mentioned above must also be reviewed.

Upgrading from Mica 6.x requires some attention from the system administrator: Agate must be upgraded to [5.0](/news/release/agate/5.0/) first, as the new sign-in page assumes that Agate verifies the password before asking for the 2FA code. No database migration runs at startup. Please read the [Mica upgrade notes](https://github.com/obiba/mica2/blob/master/UPGRADE.md) before upgrading.

See also the [Mica documentation](https://micadoc.obiba.org/) for installation and operation instructions.
