title: Mica 7.0 Released
date: 2026-10-22T12:00:00Z # after Agate 5.1
product: mica
summary: 2FA sign-in feedback, open redirect closed, XSS hardening, credentials kept out of logs
---

We are pleased to announce that Mica 7.0 is now available. [Mica](/products/mica/) is OBiBa's data web portal for epidemiological studies and harmonization initiatives.

This is a security-focused major release, with the following key changes:

- **Two-factor authentication feedback**: a wrong 2FA code keeps the 2FA step open and shows "Invalid or expired code", instead of returning to the credentials form with a generic failure.
- **Open redirect closed**: the `redirect` parameter of the sign-in, sign-up and `/check` pages only accepts a path on the Mica server or a URL on the Agate server.
- **Credentials kept out of logs**: remote credentials for the study import are sent in request headers instead of query parameters, and session IDs no longer appear in logs.
- **XSS hardening**: security response headers, Markdown sanitized with DOMPurify, safe custom page names, and uploaded files displayed inline only for PDF, raster images, plain text, CSV and TSV.
- **Authorization on administration endpoints**: changing log levels and custom translations requires the `mica-administrator` role.
- **Roles mapping applied everywhere**: the Agate groups mapped through the `roles.<role>` settings are now used for notifications, user lists, sign-up and contact, not only at sign-in.
- **Clean deletions**: deleting a data access request or an entity removes all of its permissions, comments, collaborators and files.

It also brings a few new features:

- Editors and reviewers are notified when an entity or a file is published or unpublished; readers of private comments on data access requests (e.g. a data access committee) are notified of these comments.
- Files attached to a data access form can be downloaded as a ZIP archive.
- Research project files can be browsed from the published project page.

**Breaking changes:**

- **Overridden templates** must be revised from the 7.0 versions (full list in the upgrade notes). Otherwise, Markdown is displayed as escaped text (`libs/scripts.ftl`), the contact form ends on a "not found" page (`libs/contact-scripts.ftl`), and dark-mode visitors get AdminLTE's dark theme (`libs/head.ftl`).
- **Custom page names** may only contain letters, digits, `_` and `-`, and must not be the name of a bundled template.
- **Redirect links** to an absolute URL after sign-in (`?redirect=https://...`) must use a local path.
- **API clients**: the study import takes the remote credentials in the `X-Mica-Remote-Username` and `X-Mica-Remote-Password` headers (a reverse proxy must let them through); `HEAD /ws/auth/session/{id}` only answers for the caller's own session; the log level and custom translation endpoints require the `mica-administrator` role.
- **Roles mapping**: emails may now go to different Agate groups. Only groups that grant a role on their own are used (with `a,b|c`, only `c`).
- **Inline files**: SVG, HTML and other types are always downloaded; pages embedding them inline must be revised.
- **Response headers**: Mica now sends `X-Content-Type-Options`, `Referrer-Policy` and (over TLS) `Strict-Transport-Security`. If a reverse proxy already sets them, remove them from the proxy configuration to avoid duplicates.
- **New emails**: where the notifications of an entity type are enabled, editors and reviewers now also receive an email when an entity of that type is published or unpublished.
- **Custom translations**: add the new `sign-in-otp-failed` and `files` messages to any language other than English and French.

Upgrading from Mica 6.x requires some attention from the system administrator:

1. **Upgrade Agate first** to at least [5.1](/news/release/agate/5.1/): Mica relies on Agate checking the password before the 2FA code, and on its publication email templates.
2. **Clean up orphaned data** left by entities deleted with earlier versions (no migration runs at startup). The `dar-orphan-cleanup.js` and `entity-orphan-cleanup.js` scripts, in `/usr/share/mica2/tools` (Debian/RPM packages and Docker image) and in the [repository](https://github.com/obiba/mica2/tree/master/mica-dist/src/main/tools), run in `mongosh` against the `mica` database. They do a dry run by default; back up the database and stop Mica before applying. Each script's header gives the exact commands, including for Docker Compose.

Please read the [Mica upgrade notes](https://github.com/obiba/mica2/blob/master/UPGRADE.md) before upgrading.

See also the [Mica documentation](https://micadoc.obiba.org/) for installation and operation instructions.
